Comment ça marche

1. Crée un bouton

Donne-lui un nom (pour toi, pas affiché au client), un âge minimum, et éventuellement une URL de redirection. Tu peux créer plusieurs boutons avec des seuils différents (ex: 18 ans pour l'entrée, 21 ans pour certains alcools) — chacun a son propre code à intégrer et ses propres informations demandées. Exemple : un contrôle d'accès n'a besoin de rien de plus que le résultat, un service qui doit enregistrer l'identité voudra le nom et la date de naissance, une administration voudra en plus la date d'expiration du document — coche uniquement ce dont tu as besoin, le visiteur voit toujours ce qui lui est demandé avant de valider.

2. Colle le code sur ton site ou ton app

Chaque bouton généré ci-dessous te donne un bloc HTML prêt à copier-coller à l'endroit de ta page où tu veux afficher "Vérifier mon âge". Aucune inscription ni compte développeur nécessaire — c'est un simple bouton HTML.

3. Ce qui se passe quand un visiteur clique

Sur ordinateur : un QR code s'affiche. Le visiteur le scanne avec son téléphone, qui ouvre la vérification là-bas.
Sur mobile, déjà connecté à amalgamG3 : vérification en un clic, aucun scan nécessaire.
Sur mobile, pas connecté : le visiteur est invité à se connecter ou créer un compte, puis revient automatiquement terminer la vérification.
Dans tous les cas, tu ne reçois que le résultat (vérifié/refusé/compte non vérifié/expiré) et les informations que tu as cochées à l'étape 1 pour ce bouton — jamais la pièce d'identité elle-même. Si tu as coché "date de naissance", tu la reçois en clair ; sinon, seul l'âge calculé et le résultat te sont transmis. Le visiteur voit toujours ce qui va être partagé avant de valider.

4. Récupère le résultat sur ton site

Avec URL de redirection (recommandé si le bouton ouvre une page, pas une popup) : le visiteur est automatiquement renvoyé vers l'URL que tu as configurée, avec le résultat dans les paramètres de l'adresse : ?verified=true&result=verified&name=Jean+Dupont&age=25. Ta page n'a qu'à lire ces paramètres pour savoir quoi faire (débloquer le contenu, afficher un message, etc.).
Sans URL de redirection : le code copié inclut déjà un script qui écoute le résultat via postMessage (utile si le bouton ouvre une popup au-dessus de ta page, sans la quitter). Regarde les commentaires dans le code copié pour brancher ta propre logique.

5. Utilisation dans une app (Android/iOS)

Si ton app est une "WebView" (elle affiche une page web dans l'app, via des outils comme AppCreator24, Median.co, WebIntoApp...), le bouton fonctionne directement, à condition d'avoir activé l'autorisation caméra pour la WebView (nécessaire pour scanner le QR ou pour badger via NFC côté commerçant). Pour une app 100% native (pas de WebView), utilise la redirection (étape 4) : elle fonctionne aussi depuis une app en ouvrant le lien dans le navigateur du téléphone.

6. Gérer tes boutons avec Claude

Plutôt que de tout faire depuis cette page, tu peux connecter ton compte commerce à Claude et lui demander directement de créer, modifier ou lister tes boutons, de te donner le code à intégrer, ou de mettre à jour ton profil commerce — le tout en langage naturel.

Mise en place (aucune installation) : va dans l'onglet IA & MCP, génère ton lien, colle-le dans Claude → Paramètres → Connecteurs. Ce lien ne donne accès qu'à ton propre compte commerce, jamais à l'admin ni aux autres comptes.

Tu utilises Claude Code avec un serveur local plutôt qu'un connecteur ? Voir mcp-server/README.md pour l'option avancée.

Sécurité

Chaque bouton a un identifiant unique et n'est lié qu'à ton compte commerçant — personne d'autre ne peut voir tes boutons ni leurs résultats. Chaque vérification est journalisée (visible dans les logs internes de ton compte).

Si renseignée, le visiteur est automatiquement redirigé vers cette page après le scan, avec le résultat et les informations cochées ci-dessous dans l'URL. Sinon, la fenêtre se referme simplement et le résultat est transmis via postMessage uniquement.

Ne coche que ce dont tu as réellement besoin — par exemple un contrôle d'âge simple n'a besoin de rien de plus que le résultat, alors qu'un service qui doit enregistrer l'identité du visiteur aura besoin du nom et de la date de naissance.
